Effort levels and model picker

Five effort levels, from Claude Code. The model picker shows all five.

Low
Medium
High
Extra High
Max
ItemDetail
Levelslow, medium, high, xhigh, max (shown as Low, Medium, High, Extra High, Max)
ModelsOpus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.2
DefaultHigh, when the model supports it; a model without High has no default effort
Config keyThe picker writes model.config.thinkingLevel (values low, medium, high, xhigh, max)
1M suffixThe model ID keeps a 1m suffix for Opus models; date suffixes are dropped
Below the listEffort, a Fast mode toggle and a 1M context toggle
Selection id@provider=<provider>:<modelId>; an id with no prefix (or no colon) falls back to the copilot provider with the original id as the model, and explicitProvider is false. That keeps an old session on the host default transport instead of moving it
Picker buttonShows the current model, e.g. Sonnet 5.5
ShortcutsOption+P / Alt+P switch model; Option+O / Alt+O toggle fast mode
Level the model lacksClaude Code falls back to the highest supported level at or below the one set; xhigh runs as high on Opus 4.6 (Opus 4.6 and Sonnet 4.6 list low, medium, high, max). Source: https://code.claude.com/docs/en/model-config, fetched 2026-11-26. Not implemented in the Agent Host: in microsoft/vscode@1.148.0 agentHost the picker lists only the levels each model advertises (createClaudeThinkingLevelSchema, common/claudeModelConfig.ts), and the chosen level, including max, is passed through unchanged (toRuntimeEffortLevel); no code there maps xhigh to high.
Default shownThe picker default is High when the model lists High (claudeModelConfig.ts). The Claude Code docs give a different default for some models (Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.2: medium), so the effort Claude Code runs with when nothing is picked can differ from the picker default.
