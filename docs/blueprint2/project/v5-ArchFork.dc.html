why
Why a direct fork, not VSCodium
VSCodium's last release is 1.143 (28 Oct) while VS Code is at 1.148 (25 Nov), and VSCodium had 2 commits last month. OmnIDE forks microsoft/vscode at a release tag, rebases per upstream release, and borrows only VSCodium's telemetry-off and Open VSX patches.
build
Packaging
Code-OSS gulp packaging (vscode-darwin-arm64-min, win32-x64, linux-x64) plus our own Apple signing and notarization. OmnIDE code ships as a built-in extension; core patches only where an extension cannot reach: title bar, layout, brand.
never assumed
What Microsoft receives
Nothing. No Microsoft endpoints in product.json, experiments and natural-language search off, extensions from Open VSX, updates from OmnIDE's own GitHub Releases, no Microsoft telemetry built-in extensions.
telemetry
OmnIDE's own sender
Crashes, errors and performance go to Sentry through @sentry/electron; dataCollection omits IP and request bodies. On in dev and test builds. Opt-in on public builds, through the first-run screen and a Settings > Privacy toggle.
upstream
Keeping up with upstream
Both upstreams are pinned in upstream.json: microsoft/vscode at 1.148.0 and VSCodium at a tag. Renovate (free on GitHub) opens one PR per new release. CI on that PR applies our patches, builds and runs smoke tests; a patch that no longer applies fails the PR and nothing merges red. Goes in with build milestone 1.
agent
Agent runtime: VS Code's Agent Host
OmnIDE reuses upstream VS Code's built-in Agent Host (src/vs/platform/agentHost, MIT, shipping in 1.148.0) and its Claude harness (node/claude, on @anthropic-ai/claude-agent-sdk), not claude-agent-acp or ACP. The SDK points at the user's own installed claude (pathToClaudeCodeExecutable), is fetched on demand into sdk-cache and is not bundled. Microsoft's Copilot proxy auth path (claudeProxyAuth) is off. Other agents on the v0.2 roadmap are the Agent Host's other harnesses, roadmap only.
