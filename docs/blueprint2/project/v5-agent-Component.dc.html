Agent: how the pieces connect

The Agent panel is not code inside the editor core. It is the built-in extension omnide.agent, a client of VS Code's own Agent Host (src/vs/platform/agentHost, MIT, shipping in 1.148.0). The Agent Host runs its Claude harness (node/claude), which drives the user's own installed claude through @anthropic-ai/claude-agent-sdk (pathToClaudeCodeExecutable). The SDK is fetched on demand into sdk-cache, not bundled, and Microsoft's Copilot proxy auth path (claudeProxyAuth) is turned off. Nothing talks to Anthropic except Claude Code itself.

Why the Agent Host and not our own adapter
The Agent Host ships in VS Code, so protocol and Claude harness updates arrive with each upstream rebase. Other agents on the v0.2 roadmap (Codex and others) are the Agent Host's other harnesses, shown only as roadmap, with no UI change.
Why the extension is built in
It ships inside the app, signed with it, and Open VSX is not needed to get the agent. It uses the same extension API as any extension, so a fork never patches the core for it.
Auth
Sign-in is Claude's own: OmnIDE opens a terminal running claude /login. OmnIDE never sees or stores Claude credentials and has no account. No CLI is bundled; it runs the user's installed claude. An API key is optional, for users without a plan, and is kept in VS Code SecretStorage.
