Shift+Tab mode cycle

Each press moves to the next mode: Manual, Accept edits, Plan, then Bypass permissions if it is available, then Auto if it is available, then back to Manual. From Auto the first press goes to Manual. Windows fallback: Alt+M. Order read from the installed Claude Code 2.1.332 (its mode-cycle function) and stated in the permission-modes docs.

When Bypass and Auto join the cycle

ItemRule
Bypass permissions is in the cycleOnly when the session starts with --permission-mode bypassPermissions, --dangerously-skip-permissions or --allow-dangerously-skip-permissions, or with permissions.defaultMode: "bypassPermissions" in user settings, in --settings or in managed settings. The --allow- flag adds the mode to the cycle without turning it on. A session started without any of these cannot enter Bypass permissions mid-session. Cross-session messaging still prompts in this mode (see Never auto-approved).
dontAskNever in the cycle. The VS Code extension's mode indicator lists Manual, Edit automatically, Plan, Auto and Bypass, with no dontAsk
AutoLeaves the cycle when disableAutoMode is "disable" in managed settings; a session started with --permission-mode auto then starts in Manual
Project settingsauto set in .claude/settings.json or .claude/settings.local.json does not take effect (the built-in default is used); bypassPermissions there does not take effect and the session starts in Manual. Set it in ~/.claude/settings.json. Other values apply from any settings file.

Starting mode: what the docs say and what OmnIDE starts on

QuestionAnswer
Is Auto the starting mode in Claude Code?Yes, from v2.1.283: "auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions." Earlier versions start in Auto only on Pro, Max, Ultra and Team plans, in sessions that fetch feature flags; otherwise the built-in default is Manual. The same page also states the built-in auto default needs v2.1.228 or later on macOS, Linux and WSL and v2.1.233 or later on native Windows; the two thresholds are not reconciled in the docs.
Which plans and models?The docs list all plans; on Team and Enterprise it is on unless an admin sets permissions.disableAutoMode to "disable". Models: Opus 4.6+, Sonnet 4.6+, Haiku 5.5 or a Fable model on the Anthropic API; Sonnet 5+, Opus 4.7+, Haiku 5.5 or Fable on Bedrock, Google Cloud Agent Platform and Foundry.
If Auto is unavailableThe session starts in Manual: a settings file turning it off, an unsupported model, or Anthropic turning it off server-side.
Claude Code VS Code extensionSetting claudeCode.initialPermissionMode accepts default, manual, acceptEdits, plan or bypassPermissions, not auto. Order for a new conversation: that setting, then the last mode picked (Manual, Edit automatically or Auto), then permissions.defaultMode from managed or ~/.claude/settings.json, then the built-in default.
What OmnIDE's picker starts onAsk Before Edits (Manual). The Agent Host schema for Claude sets the Approvals property permissionMode with default: 'default' (claudeAgent.ts:2306) and validates new sessions against default (claudeAgent.ts:2315); the five labels are Ask Before Edits, Edit Automatically, Plan Mode, Auto Mode and Bypass Permissions (claudeAgent.ts:2293-2297). The code gives no written reason for the choice. Reading of the code: the host always passes an explicit permissionMode to Claude (claudeAgent.ts:1830, falling back to 'default'), so Claude Code's own built-in starting mode never applies.
Docs and code disagreeYes. The docs say a new interactive Claude Code session starts in Auto from v2.1.283; the Agent Host of microsoft/vscode 1.148.0 starts in Manual. Auto is used there only for autonomous sessions (getAutonomousSessionConfig, claudeAgent.ts:2338-2342, unless the host policy AgentHostAutoApprovePolicyRestricted is true). This page does not change the choice; it is open for the owner.

Auto mode pause ruleWhat the docs say
TriggerIf the classifier blocks an action 3 times in a row or 20 times in total, Auto mode pauses and Claude Code goes back to asking.
ResumeApproving the action it then asks about resumes Auto mode.
CountersThe two limits are not configurable. The total counter lasts for the session and resets only when its own limit triggers a fallback. A denial from a separate safety check that refuses the classifier's own request counts toward neither.
Non-interactive -p run with no --permission-prompt-toolThere is nothing to ask, so the blocked action does not run and Claude keeps working; the run is not stopped.

What each mode does without asking

ModeBehaviour
Manual (default)Reads inside the working directories and actions that need no approval run; most edits, shell commands and network actions prompt
Accept editsFile edits in the working directory (or an added directory) run without asking, and so do mkdir, touch, rm, rmdir, mv, cp and sed there. Paths outside, protected paths, other shell commands and critical-path removals still prompt
PlanClaude reads files, runs exploratory commands and writes a plan; it edits no source until the plan is approved. Enter by Shift+Tab, by starting one prompt with /plan, or with --permission-mode plan. Leave with Shift+Tab when no approval prompt is open
Plan approval in the CLIThree choices: Yes, and use auto mode; Yes, manually approve edits; No, keep planning. Press Esc first to leave: at this prompt Shift+Tab approves the plan. In the Agent Host the same card shows Approve and Deny (see the plan approval screen)
AutoEverything runs, and a separate classifier model reviews each action and blocks risky ones
dontAskReads and pre-approved tools run; anything that would prompt is denied
Bypass permissionsRuns everything except deny rules and the prompts listed on Never auto-approved
