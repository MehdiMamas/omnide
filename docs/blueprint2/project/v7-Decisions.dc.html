Decisions

What was chosen, what was turned down and why. Newest first. Six modes exist, OmnIDE uses five (dontAsk not offered).

Auto-review skips; the card appears only on a pause or an ask rule

In auto mode Claude Code does not ask for each action: the classifier lets safe ones run and blocks the rest.

  • Chosen: A blocked action is skipped with a notice and listed under Recently blocked, each with Run once and Always Run. The card shows only when auto pauses (3 blocks in a row or 20 in total) or an ask rule matches. The example rule is narrow, Bash(npm test); auto drops broad rules such as Bash(*).
  • Rejected: Show the Run, Skip, Always Run card on every block: auto never asks per action, so the card would promise a prompt Claude Code does not send
  • Rejected: Let Always Run save a broad rule such as Bash(*): auto drops broad allow rules, so the click would do nothing

Allowlist is acceptEdits plus allow rules

Cursor-style Allowlist applies edits and shows them for review, and asks for commands.

  • Chosen: Start Claude Code in acceptEdits with the allow rules: edits are applied and shown with Keep or Undo, other commands not on the allowlist ask, except mkdir, touch, mv, cp and sed in the working folder (acceptEdits approves those); rm, rmdir and git rm still ask. The fallback when Auto is unavailable is the same.
  • Rejected: default mode plus allow rules: every edit would ask first, which is not how Allowlist works in Cursor-style review and trains users to click through

Ask is default mode with call-time refusal of edits, not deny rules

Claude Code has no answer-only mode.

  • Chosen: Start in default mode with all tools present; the permission callback (canUseTool) refuses Edit, Write and NotebookEdit while the chat is in Ask. Shell commands still go through the card. The bar reads No edits.
  • Rejected: plan mode plus a never-propose-edits rule: plan mode auto-approves commands during the plan and ends with a plan-approval prompt, neither of which an answer-only chat should have
  • Rejected: Deny rules on Edit, Write and NotebookEdit: found in a real run: Claude Code drops a denied tool when the session starts and never brings it back, so a chat that started in Ask stayed unable to edit after Shift+Tab to Agent
  • Rejected: Ask as Agent with all tools denied: Claude could not read files to answer
  • Rejected: Drop Ask and keep Plan only: issue #19 asks for three modes, and a pure question should not produce a plan

OmnIDE never writes the user's global Claude settings

The user's ~/.claude/settings.json also drives their CLI.

  • Chosen: Each chat is started with --permission-mode (the SDK permissionMode option) and OmnIDE keeps Run Mode in its own settings. Allow rules from Always Run go to the workspace .claude/settings.local.json. Run Everything chats start with allowDangerouslySkipPermissions.
  • Rejected: Write permissions.defaultMode to ~/.claude/settings.json: it would change how the user's terminal Claude behaves without them asking

Run Everything gets OmnIDE's own one-time dialog

Claude Code shows its bypass warning in a terminal; the Agent Host is not one.

  • Chosen: OmnIDE shows the warning once and stores the acceptance in its own settings. skipDangerousModePermissionPrompt is never written. The option is greyed when managed settings disable it.
  • Rejected: Write skipDangerousModePermissionPrompt ourselves: it hides the one warning that explains the risk and edits a global file
  • Rejected: Hide the option when disabled: the user cannot see why a mode they expect is missing

Protections are best effort, and there is no browser protection

Claude Code rules match command text and paths.

  • Chosen: File deletion (on) uses ask rules and can be bypassed with find -delete, git clean and the like. External files (on) uses blockWritesOutsideWorkingDirectories, which refuses rather than asks. Both are labelled best effort in Settings. The browser protection is dropped: Claude Code has no browser tool.
  • Rejected: Promise that deletion always asks: rm rules cannot see every way a command deletes a file
  • Rejected: Keep a Browser protection toggle: there is no tool for the rule to match

No sandbox toggle on Allowlist

The issue mentioned an optional sandbox.

  • Chosen: Dropped for now. Claude Code's sandbox is a separate feature and nothing fetched shows how it combines with acceptEdits. It can return as its own change.
  • Rejected: A sandbox toggle marked TO VERIFY: a switch that may do nothing is worse than none

Claims about Cursor are limited to what its docs say

Cursor's agent docs (fetched 2026-11-26) describe Agent, Plan and Ask. They do not cover Run, Skip and Always Run.

  • Chosen: Say that the buttons are our proposal. Note that Cursor's Auto-review is sandboxed and takes natural-language instructions, and Claude's auto does neither.
  • Rejected: Describe the card as copied from Cursor: the sources do not show that

Two settings, Mode and Run Mode

Claude Code has one list of modes that mixes what Claude does with how much it asks. Cursor's docs list Agent, Plan and Ask as modes, and the owner chose this split on 2026-11-26.

  • Chosen: The chat picker holds Agent, Plan and Ask. Settings holds Run Mode: Auto-review, Allowlist, Run Everything. Together they map onto Claude Code modes.
  • Rejected: Show Claude Code's modes in one picker (default, acceptEdits, plan, auto, bypassPermissions): Shift+Tab would reach bypassPermissions, and users cannot tell "what Claude does" from "how much it asks"
  • Rejected: Also offer dontAsk: it is for non-interactive CI runs and would make a chat silently refuse anything not allowed

New chats start in Agent with Auto-review

A default has to be safe and useful without setup.

  • Chosen: Agent with Auto-review, configurable in Settings. Where Auto is unavailable the chat starts in Allowlist with a notice.
  • Rejected: Start in Allowlist everywhere: asks far more often and teaches users to click Always Run without reading
  • Rejected: Start in Run Everything: turns approvals off before the user chose it
