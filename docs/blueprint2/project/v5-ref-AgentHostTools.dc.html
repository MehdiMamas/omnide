Permissions, tool kinds, plans and commands

What the Agent Host sends for a tool call and how the panel answers it.

TopicDetail
Permission optionsConfirmationOptions of kind approve or deny: allow-once, allow-session and a skip option (plus rule-based grant options)
Who remembersThe host's SessionPermissionManager (session scope; host scope writes the root permissions config). The Claude agent remembers nothing
PlansNo plan channel. TodoWrite and Task* tools are ordinary tool calls shaped for display; plan mode ends with ExitPlanMode as an Approve or Deny confirmation, never remembered. Approve writes permissionMode=acceptEdits to the config, not live: calling setPermissionMode during the permission reply sends a second control request on the channel the SDK is waiting on, the SDK loop collides with it and the turn never resumes. The next send forwards the mode between turns. Declining ExitPlanMode returns "The user declined the plan, maybe ask why?"
Deny texts and codesA denied tool permission returns "User declined" (code denied). Declining ExitPlanMode returns "The user declined the plan, maybe ask why?" (code denied). A cancelled AskUserQuestion returns "The user cancelled the question" (code cancelled). Any other failed tool result has no code and counts as a tool error
Under BypassAskUserQuestion and ExitPlanMode still reach the permission check; they are never auto-approved
ToolKindterminal, subagent, fusionPhase, search, read. Bash maps to terminal, Read to read, Grep and Glob to search, Task and Agent to subagent; other tools get no special kind
Local commands/rename [title] (becomes SessionTitleChanged, only offered once a session has history) and !command (runs as a terminal command shown as a terminal tool call). No Claude-specific slash handling; parseLeadingSlashCommand is used only by the Copilot and Codex agents
