How a new OmnIDE reaches a running app

Planned, same model as VSCodium (not in the merged build: product.overrides.json sets no updateUrl): product.json will point updateUrl at a static latest.json on GitHub Pages (https://mehdimamas.github.io/omnide/latest.json) and downloads come from GitHub Releases, so updates cost nothing to host. Linux builds update through their package manager.

  1. On start and on a timer the app fetches latest.json from GitHub Pages.
  2. Newer than this build? If not, nothing happens.
  3. The release asset downloads from GitHub Releases in the background.
  4. Its sha256 is checked. Mismatch: the file is deleted, nothing changes, and the user sees Update couldn't be verified; the app tries again at the next check, or on Retry now.
  5. Match: the user sees Restart to update. The update installs on restart and windows and chats reopen.

Never assumed

That the download is intact: the checksum is verified and the installer is signed (macOS notarized; Windows via SignPath if accepted, see Questions Q4).

To verify

Code - OSS asks the update URL for /api/update/platform/quality/commit; VSCodium patches that into a static path. Read its patch before copying. The check interval is not confirmed.
