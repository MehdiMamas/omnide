Build and CI

How OmnIDE is built from the pinned upstream tag, and what CI runs on every push and pull request, as merged in PR #17 (dc22b05). The build workflow smoke-tests the built CLI and archives it on all three platforms.

StepWhat it does
1scripts/prepare_vscode.sh: reads repo and tag from upstream.json; if vscode/.git is missing it runs git init, adds remote origin https://github.com/<repo>.git and sets core.autocrlf false; then fetch --depth 1 of the tag, checkout -f and clean -fdq. It then compares HEAD with the commit pinned in upstream.json and exits 1 if they differ ("upstream tag is X, upstream.json pins Y"), so a moved tag cannot slip in.
2scripts/patches.sh: for each patches/*.patch, in file order, git -C vscode apply --whitespace=nowarn (prints "applying <name>"). Runs under set -euo pipefail: the first patch that fails stops the script and the build, so the pull request's CI is red and nothing merges
3scripts/assets.sh: copies the icons (omnide.icns to resources/darwin/code.icns, omnide.ico to win32/code.ico, omnide.png to linux/code.png, code_150x150.png and code_70x70.png to win32/), the Geist .woff2 fonts to src/vs/workbench/browser/media/fonts/, and extensions/theme-omnide/package.json plus src/omnide/theme/*.json to vscode/extensions/theme-omnide/themes/; then merges product.overrides.json into vscode/product.json with jq (see Patch series)
4cd vscode; pnpm install --frozen-lockfile; pnpm run gulp "vscode-<target>-min"

scripts/build.sh is the local build: prepare_vscode.sh, patches.sh, assets.sh, install, gulp, in that order (no smoke or archive). With no argument it picks the target from uname: darwin-arm64, darwin-x64, linux-x64 or win32-x64. The workflow runs the same scripts step by step.

Smoke stepRuns the built CLI with --version (win32 bin/omnide.cmd, macOS OmnIDE.app/Contents/Resources/app/bin/omnide, linux bin/omnide) and fails unless the first line, carriage return removed, equals the tag in upstream.json. It proves the built app starts and is the pinned upstream version; it does not open a window.
Archive stepKeeps permissions and symlinks: macOS ditto -c -k --keepParent; Linux tar -czf; Windows 7z a -tzip
Artifactupload-artifact of the archive as omnide-<target>, if-no-files-found: error, retention-days: 7
Pinned actionsEvery action is pinned to a full commit SHA with the version in a comment: checkout 11d5960a (v4.4.0), setup-node 49933ea5 (v4.4.0), upload-artifact ea165f8d (v4.6.2). The same pins are in lint.yml

Windows build fixCause and fix
Relative path to upstream.json (commit 780270c)prepare_vscode.sh read upstream.json with require('$root/upstream.json'). On the Windows runner $root is an MSYS path (/c/...) that Node cannot resolve. The script now runs cd "$root" and reads require('./upstream.json'), a relative path.
No CRLF conversion (commit b59664f)Git for Windows converted line endings in the upstream checkout and in the patches, which broke the brand fonts patch (now 0006). Fixed twice: .gitattributes holds *.patch -text and *.sh text eol=lf, and prepare_vscode.sh sets core.autocrlf false on the new vscode/ repo.
