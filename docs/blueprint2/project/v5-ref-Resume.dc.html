Resume and sessions

What happens when a chat is reopened, by id or from history, and which errors it can show.

CaseWhat the user doesResult
Resume by an id that does not existclaude --resume <session-id>Claude Code prints: No conversation found with session ID: <session-id>. It resolves an id only when exactly one project holds a transcript with messages for it, so a hand-copied duplicate also reports not-found
Session ended in BypassResume it laterBypass is not restored. The resumed session starts in the mode a new session would start in; to bypass again the user enables it at launch or in settings (permissions.defaultMode)
Session ended in PlanResume it laterTerminal resume returns to Plan mode; with fork-session it starts in the mode a new session would start in
Open a saved chat in the Agent HostPick a chat from HistoryThe saved-chat reader loads its transcript through the SDK, then the next send resumes the session
History reader missingOpen a saved chat while the SDK is not installedThe chat shows: The local Claude history reader is not available.
Backing missingOpen a saved chat whose session file is goneThe chat shows: The saved Claude chat backing is missing or invalid.
Restore CheckpointRewind to a turnSame session id, turns 0..N kept; see session, turn and cancel
Name, fork and clear/resume, /branch, /clearSee Sessions, resume and fork
