Agent Host link and environment

How the workbench reaches Claude: VS Code's built-in Agent Host, no adapter. Channels look like ahp-session:/<uuid>.

PartDetail
Spawned byelectron-main (UtilityProcess, entry vs/platform/agentHost/node/agentHostMain); connect() gives the port
In OmnIDEThe SDK is fetched on demand into sdk-cache and pointed at the user's own installed claude (OmnIDE code still to be written, not one of patches 0001 to 0008); the Copilot proxy is off
Native mode envFull process.env plus ELECTRON_RUN_AS_NODE=1, NODE_OPTIONS cleared; ANTHROPIC_API_KEY or CLAUDE_CODE_OAUTH_TOKEN (from claude setup-token) pass through
Proxy mode env (Copilot)Sparse (HOME, USERPROFILE); ANTHROPIC_API_KEY unset; ANTHROPIC_BASE_URL and ANTHROPIC_AUTH_TOKEN carry a nonce.sessionId bearer
Both modesVSCODE_* and ELECTRON_* variables are stripped
SDK lookup order1) the env var AgentHostClaudeSdkRootEnvVar (--claude-sdk-root, for air-gapped hosts and out-of-tree builds); 2) the downloader, when the product config product.agentSdks.claude is present: cache first, else fetch the per-host tarball (a missing install reads "The Claude history reader is not installed." when downloads are off); 3) a bare import, development launches only
SDK download statusFour values: notDownloaded, downloadOnUse (absent, but the host remembers consent and fetches it when a turn needs it), downloading, ready. Account state is not on this channel: ready with zero models means no account
Not signed in (proxy transport)With a proxy transport and no auth handle, _ensureAuthenticated throws ProtocolError AHP_AUTH_REQUIRED, message "Authentication is required to use Claude"; the client then answers authenticate. Native transport never raises it
Account set upisClaudeAccountSetUp is true when apiProvider is set and not firstParty, or tokenSource is set and not "none", or apiKeySource is defined. It means configured, not working: no billable request is made to check
Settings > Claude statesFour: not installed; installed but signed out; signed in; API key (the key is kept in SecretStorage). A failed connection shows the error screen
