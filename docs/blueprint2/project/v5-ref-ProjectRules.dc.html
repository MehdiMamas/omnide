Project rules: contributing, conduct, credits

What the repo asks of everyone who changes OmnIDE, read from the files themselves.

How work is planned (CONTRIBUTING.md)

RuleWhat it says
Issue firstEvery change starts as an issue; big ones link to the roadmap.
Comment before you startSo two people do not build the same thing.
Ideas and questionsGo to Discussions, not issues.

Ground rules (CONTRIBUTING.md)

RuleWhat it says
1 Clean roomNever copy code, icons, images, text or assets from proprietary editors, Cursor included. Build from public behaviour. PRs that copy are closed.
2 Patches stay smallChanges to Code - OSS live in patches/, as small as possible; prefer a built-in extension over a core patch.
3 No credential handlingOmnIDE never asks for, stores, proxies or logs a provider login or token; agents run as their own official programs.
4 Close means stopAnything spawned is tied to the window process tree and ends when it closes.
5 No telemetryUnless it is opt-in and documented.
