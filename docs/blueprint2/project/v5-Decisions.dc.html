Decisions

What was chosen, what was turned down and why. Newest first.

Nothing is locked or paid

OmnIDE is free and open source, so no screen, setting or model may be gated.

  • Chosen: No Upgrade, Pro, plan or usage-limit UI; other agents are only Roadmap v0.2 entries in the agent picker, with no padlock.
  • Rejected: Keep padlocks as teasers: a free product has nothing to sell; a padlock reads as a paywall
  • Rejected: Hide other agents: the roadmap is worth showing, as a plain label

Drop Cursor-only screens

Cloud agents, voice, browser tool, tab completion and review bot need a service OmnIDE does not run.

  • Chosen: List each on Not in OmnIDE with a reason and where the need goes.
  • Rejected: Show them locked: they would look like a paid tier
  • Rejected: Silently remove them: the owner could not see what was cut and why

Design the Claude Code features that differ from the reference IDE

The owner asked for the things that set OmnIDE apart.

  • Chosen: Model and effort, context meter, compact, plan approval, subagents, todos, rewind, fork, sessions, background tasks, rate limit and About each get a screen.
  • Rejected: Reuse the reference IDE screens only: they hide what Claude Code does differently

No OmnIDE account

Claude Code signs in with the user's own Claude login.

  • Chosen: Settings > Claude replaces Account and Plan and Usage.
  • Rejected: An OmnIDE account: needs a server, a cost and a privacy policy for no gain

Publish v4 as a new artifact

The v1 to v3 artifact reached the 511-file limit.

  • Chosen: New artifact for v4; the old one is kept as the archive.
  • Rejected: Delete old boards to fit: history would be lost

Design starts as a copy of OmnIDE As-is

The owner rejected the v1 scratch design on 2026-11-26: it was nowhere close to the OmnIDE As-is canvas.

  • Chosen: Copy the 265 OmnIDE v2 boards, keep names, positions and sizes, and change only what OmnIDE needs.
  • Rejected: Keep and tweak the v1 scratch design: the owner already said no to it
  • Rejected: Redraw the screens by hand: slow, and it drifts from the reference the owner wants to see

Purple accent

The owner's words: "i am a purple guy, make it purple instead of the lime".

  • Chosen: Purple #7C3AED is the accent; buttons use #6D28D9 (7.1:1 with white); #B69CFF for links and focus on dark. It also stands apart from the blue of VS Code, Zed and Copilot.
  • Rejected: Teal (v1): the owner did not want it
  • Rejected: blue (VS Code, Zed and Copilot already use it)

Claude Code through VS Code's Agent Host

The first agent has to work on day one without OmnIDE building an agent.

  • Chosen: Claude Code through the Agent Host that ships in VS Code 1.148.0 (ClaudeAgent on @anthropic-ai/claude-agent-sdk, driving the user's own installed claude), using the user's own Claude Code sign-in or an API key. Codex and Copilot, the Agent Host's other providers, come in v0.2.
  • Rejected: Build our own agent: Void did that and was archived on 2026-06-02
  • Rejected: Bundle Anthropic's SDK in the app: OmnIDE would handle the user's tokens; the Agent Host keeps them in Claude Code

Thin patches on Code - OSS

One maintainer has to be able to keep up with upstream.

  • Chosen: Scripts plus a patches folder, built in GitHub Actions, like VSCodium; extensions from Open VSX.
  • Rejected: A full fork like OmnIDE or Void: months behind upstream, hard to maintain
  • Rejected: A new engine like Zed: years of work and no VS Code extensions

Updates from GitHub Releases

No server to run or pay for.

  • Chosen: A static latest.json in a versions repo and the installer on GitHub Releases, sha256 checked.
  • Rejected: An own update server: costs money and needs care

No domain for now

The owner will not buy one yet.

  • Chosen: Downloads and latest.json are served from GitHub; the name stays lowercase omnide for the repo, CLI and URL scheme.
  • Rejected: Buy omnide.dev or omnide.io now: costs money; the owner said not now
