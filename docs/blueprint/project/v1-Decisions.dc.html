Agent protocol d-acp · proposed · 2026-11-26

OmnIDE must run Claude Code now and other agents later without rewriting the panel each time.

  1. Chosen: ACP (Agent Client Protocol) v1. Open, JSON-RPC over stdio, 52 agents already listed, used by Zed, JetBrains and Neovim clients.
  2. Own integration per agent. Why not: Every agent has a different API; that is the work that killed Void.
  3. MCP only. Why not: MCP gives agents tools; it does not let an editor drive an agent's turns, diffs and permissions.
How Claude Code signs in d-claude · proposed · 2026-11-26

Anthropic's terms say third parties may not offer Claude.ai login or route requests through plan credentials; an end user may sign in to the unmodified Claude Code.

  1. Chosen: Launch the official claude-agent-acp + unmodified Claude Code; it signs in itself; API key as the alternative. Same route Zed uses; OmnIDE never touches tokens.
  2. "Sign in with Claude" inside OmnIDE. Why not: Not allowed by Anthropic's terms for third-party products.
  3. API key only. Why not: Allowed, but forces Pro/Max subscribers to pay twice; kept as the second option instead.
Editor base d-base · proposed · 2026-11-26

OmnIDE needs VS Code's extensions and to stay close to upstream with one maintainer.

  1. Chosen: Code - OSS + a thin patch set built by scripts (VSCodium model). Days behind upstream, all Open VSX extensions work, proven by VSCodium.
  2. Long-lived fork (Cursor model). Why not: Merges get harder every month; Cursor ran about five months behind.
  3. Own engine (Zed model). Why not: Years of work and a small extension ecosystem.
Agent panel d-panel · proposed · 2026-11-26

The panel (chat, tool cards, permissions, registry) is the main new UI.

  1. Chosen: Build on formulahendry/vscode-acp (MIT) as a built-in extension; send fixes upstream. Already has chat, permissions, registry browser and 11 agents; community keeps improving it.
  2. Write our own panel from scratch. Why not: Same features rebuilt by hand, no community updates.
Update channel d-updates · proposed · 2026-11-26

Updates must be free to host and safe.

  1. Chosen: Static latest.json in a GitHub versions repo + GitHub Releases, sha256 + code signing. Costs $0 and is what VSCodium runs.
  2. Own update server. Why not: Something to host, pay for and secure.
  3. No auto-update. Why not: Users drift weeks behind VS Code security fixes.
Product name d-name · proposed · 2026-11-26

The repo is "omnide"; read aloud it is ambiguous.

  1. Chosen: OmnIDE (display), omnide (technical ids). Reads as an IDE; technical names unchanged.
  2. Keep "Omnide". Why not: Reads as "omni-dee"; the IDE is hidden.
  3. New name. Why not: Loses the existing repo, issues and links for little gain.
